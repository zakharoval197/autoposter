## Правки дня 2 (fetcher.py / filter.py / main.py)

- fetcher: ретраи (3 попытки, backoff 2с/4с) — mos.ru рубит первый коннект.
- fetcher: `_fetch_rss` теперь забирает обложку из `<enclosure>` и дату/время из pubDate → почти 2/3 событий с реальными картинками, генерация обложек не нужна.
- fetcher: User-Agent — только ASCII! Кириллица в UA роняла ВСЕ запросы (requests кодирует заголовки в latin-1).
- filter: флаг `trusted` у источника (иначе mos.ru отсеивался целиком — в заголовках нет маркеров).
- filter: отсев не-Москвы (NON_MSK_MARKERS + «москв»-исключение) — отрезал Питер/Архангельск/Израиль.
- filter: шумные маркеры «маркет» (ловил «маркетолог») и «сет» (ловил «совет/сеть») заменены на « бар»/«сет ».
- main: **AUTOPOSTER_MAX_DRAFTS (default 5, 0 = без лимита)** — лимит черновиков за прогон, применяется ПОСЛЕ дедупликации и ДО записи в БД (обе другие расстановки ломаются: до дедупа — повторный прогон холостой; после записи — события застревают в new навсегда; поймано 05.10).
- **send_pending.py** — одноразовая рассылка всех draft-черновиков админу без запуска бота (переиспользует moderator.send_draft, карточки с кнопками). `--since N` — только id >= N (не дублировать уже отправленные). ВНИМАНИЕ: кнопки оживают только когда запущен `python main.py moderate`. Прогоны 05.10: 12 + 6 черновиков ушли админу, 0 ошибок — api.telegram.org с машины user доступен.
- Прогон с Яндекс Афишей (05.10, 21:24): 99 сырых → 47 после фильтра → 6 черновиков (#113–118: вечеринки Music Loto, Los Pollos в Gipsy, Hardcore TV и др.), все с реальными постерами.

## Известные проблемы

1. **api.moonshot.ai сломан**: русские промпты >3–4К знаков → RST через ~19 с; длинные генерации висят. EN 9К — ок. User должен отправить тикет (текст готов в переписке, 05.10). На случай бага есть skill_postmaker.en.md (EN-зеркало, авто-fallback в generator.py, SKILL_LANG=en форсирует).
2. **GigaChat пишет пресно + выдумывает факты** (придумал «сет 4 часа», «дресс-код свободный»). Модерация глазами обязательна. Идея апгрейда: DeepSeek ($1–2/мес) — OpenAI-совместимый, 3 строки в .env.
3. **api.telegram.org из РФ нестабилен** — нужен VPN (у user Happ, Kimi.exe в исключениях, остальное через туннель). В publisher.py есть 3 ретрая. Для прода — зарубежный VPS.
4. Качество картинок: для RSS-событий теперь реальные постеры; Kandinsky нужен только для событий без обложки.
5. Фильтр пропускает ~10–20% новостных статей про культуру (InterMedia/Jazz.ru проскакивают «как прошла ярмарка»). Модерация решает; можно добавить маркеры по логу filtered.
6. mos.ru иногда мешает афишу с протокольными новостями (Собянин, БПЛА) — часть отсеяна DROP-маркерами, остаток глазами.

## Эксперимент: LLM для ИИ-парсинга страниц (06.10, probe_llm_parse.py)

Тест извлечения событий из текста страницы (mos.ru/afisha/event/…, ~1400 знаков):
- **GigaChat-Max: 2,7 с, валидный JSON, факты точные** — для экстракции хватает с запасом, бесплатно.
- **Kimi (k2.6 через agent-gw): 24,7 с** (thinking-модель), валидный JSON, описание полнее (вытащил площадку — музей Голованова). Медленно и жрёт квоту подписки Kimi for Coding.

Важное про ключи (разобрано 06.10):
- KIMI_API_KEY в .env работает через **agent-gw.kimi.com/coding/v1** (OpenAI- и Anthropic-стиль оба живы), НЕ через api.moonshot.ai (там 401). Баг с RST на длинных RU-промптах относился к api.moonshot.ai — на agent-gw не проверяли, длинные прогоны пока не делали.
- **Баг был в generator.py**: base_url без `/v1` → запасной провайдер всегда 404-ил. Починено нормализацией в _chat_completion.

Рекомендация: парсинг-экстракция → GigaChat (бесплатно, быстро, точно). Kimi оставить на посты/сложные случаи, если DeepSeek не появится.

**Апдейт 06.10 (решающий тест): написание постов через Kimi РАБОТАЕТ.** Вчерашний RST-баг — специфика api.moonshot.ai; через agent-gw.kimi.com полный RU-скилл (12К знаков) + генерация прошли: 118 с на пост, 920 знаков, **ноль выдумок** (честно пишет «организаторы молчат о программе» вместо фейковых лайнапов GigaChat). Минусы: ~2 мин на пост (thinking) и расход квоты подписки Kimi for Coding. Кандидат на основной генератор постов: переключение = отдать Kimi приоритет над GigaChat в generate_post() или переменной в .env.

## Боевой тест схемы «Kimi пишет посты» (06.10, 09:30–10:20)

Итог: **схема годная, но шлюз flaky**. Из 5 попыток генерации Kimi: 2 успеха (посты #156, #157 — чистые, без выдумок), 3 обрыва → каскад ушёл на GigaChat (#207, #208, #210 — проверять глазами!).

Что сделано по коду:
- **AUTOPOSTER_WRITER=kimi|gigachat** в .env — приоритет генератора постов. Каскад: выбранный → другой LLM → мок. Пост не теряется никогда.
- **_chat_completion теперь стримит (SSE)**: thinking-модель молчит 2–4 мин, agent-gw рвёт молчаливое соединение; первый чанк за ~5 с держит его живым. Без стриминга — зависания до таймаута.
- Ретрай на обрыв: 1 повтор через 5 с до ухода на запасной провайдер.
- fetcher Яндекс Афиша: убрано поле `places` из GraphQL (их бэкенд 500-ит на нём эпизодически и валил весь источник); частичные queryErrors с данными теперь терпим.
