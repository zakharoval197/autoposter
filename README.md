# Автопостинг «Куда сходить в Москве»

Модульный пайплайн автопостинга афиши в Telegram-канал:
**сбор событий → фильтр мусора → генерация поста (Kimi API по скиллу постмейкера) → картинка с фирменной рамкой → черновик в личку → публикация после «ок».**

Ничего не публикуется без одобрения владельца.

## Структура

```
autoposter/
├── main.py             # точка входа: run / test / moderate / stats
├── fetcher.py          # сбор событий: RSS + HTML + KudaGo API (requests + BeautifulSoup)
├── filter.py           # отсев мусора по ключевым словам
├── database.py         # SQLite, таблица events (+ поле markers под базу заведений)
├── generator.py        # пост через LLM: GigaChat (основной) или Kimi/OpenAI-совместимый;
│                       # системный промпт = skill_postmaker.md, fallback на EN-зеркало
├── image_processor.py  # og:image → Kandinsky → заглушка; фирменная плашка (Pillow)
├── moderator.py        # aiogram-бот: черновик в личку, кнопки «Опубликовать/Пропустить»
├── publisher.py        # публикация в канал после «ок»
├── setup_wizard.py     # интерактивная первичная настройка .env
├── skill_postmaker.md  # скилл постмейкера (системный промпт, редактируется отдельно)
├── skill_postmaker.en.md  # EN-зеркало скилла (обход бага moonshot.ai с кириллицей)
├── .env.example        # пример настроек (заполнять руками не нужно — есть мастер)
├── requirements.txt
├── data/               # база и картинки (создаётся автоматически)
└── logs/               # pipeline.log (ротация 3 × 2 МБ)
```

## Установка и настройка

```bash
pip install -r requirements.txt
python main.py test
```

**Настройка автоматическая.** При первом запуске программа сама спросит:

1. API-ключ Kimi (Enter — тестовый режим с постами `[МОК]`)
2. Telegram Bot Token (получить у @BotFather)
3. ID канала (@username или -100…)
4. Твой Telegram ID (получить у @userinfobot)

Ответы сохраняются в `.env` — при следующих запусках вопросы не повторяются.
Чтобы изменить настройку позже, отредактируй соответствующую строку в `.env`.

## Запуск

```bash
python main.py test         # демо: 3 фейковых события; текст — реальный Kimi API,
                            # если ключ задан; картинки всегда заглушки
python main.py test --mock  # принудительный мок-текст даже при заданном ключе
python main.py run          # полный цикл: сбор → фильтр → картинка → черновики (draft)
python main.py moderate     # бот-модератор (второй процесс, держать постоянно)
python main.py stats        # статистика по базе
```

## Рабочий цикл

1. `python main.py run` (по cron) — собирает события, отсекает мусор,
   готовит черновики со статусом `draft`.
2. В личке боту пишешь `/pending` — он присылает черновики с фото и кнопками.
3. **«Опубликовать»** → пост уходит в канал, статус `published`.
   **«Пропустить»** → статус `skipped`, событие больше не всплывёт.

## Cron на VPS (сбор вечером, чтобы черновики были к 18:00–21:00)

```cron
17 17 * * *  cd /opt/autoposter && /usr/bin/python3 main.py run >> logs/cron.log 2>&1
```

Модератор — как systemd-сервис или в tmux:
```bash
python main.py moderate
```

## Логирование

`logs/pipeline.log`: что спарсилось по каждому источнику, что отфильтровалось
и по какому маркеру, источник картинки (`poster` / `generated` / `fallback`),
готовые черновики, решения модерации, публикации.

## Дальше (по брифу)

- `events.markers` (JSON) — маркеры заведений: шум, плотность, вайб, движняк в будни.
- `database` / `fetcher` / `image_processor` переиспользуются в боте-подборщике.
- Миграция SQLite → PostgreSQL: меняется только `database.py`.
